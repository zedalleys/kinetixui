# Introduction

**KinetixUI** is a design system built to move. A single design source becomes
living tokens and components that stay in sync across four platforms — the name
comes from *kinetics*: change it once, and it propagates everywhere.

- **Tokens** — DTCG token files, compiled by Style Dictionary v4 into CSS
  variables, a TypeScript object, SwiftUI, Jetpack Compose, and Flutter.
- **Components** — React + `class-variance-authority` + Radix primitives,
  styled with Tailwind against the token contract.
- **Registry** — a component registry of our own, so you `npx @kinetixui/cli add` a
  component and own the code outright.
- **This site** — built entirely on `@kinetixui/ui` and `@kinetixui/tokens`, in
  the same light and dark themes it documents.

<Callout>
  Nothing here is a runtime dependency you install and theme. You copy components
  into your app and they become yours — KinetixUI keeps them aligned with the
  design source.
</Callout>

## Who it's for

Product teams, agencies, and companies shipping on more than one platform that
want one design system, identical everywhere. KinetixUI is **free while in
beta**; deeper tooling will arrive as KinetixUI Pro.

## How it flows

<Steps>

<Step>Design tokens live as variables in the design source.</Step>

Six brand ramps, spacing, radius, and a Material-3 type scale are extracted
verbatim into `tokens/primitives`.

<Step>Semantic tokens map to the KinetixUI contract.</Step>

`tokens/semantic/color.light.json` aliases primitives to `--primary`,
`--muted`, `--ring`, and the rest. A generated `color.dark.json` mirrors it.

<Step>Style Dictionary compiles every platform.</Step>

`pnpm build:tokens` runs once per theme and writes
`packages/tokens/dist/{web,ios,android,flutter}`.

<Step>Components consume the contract.</Step>

`@kinetixui/ui` never hard-codes a hex — every colour is `bg-primary`,
`text-muted-foreground`, `border-input`.

</Steps>
