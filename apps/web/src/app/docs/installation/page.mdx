# Installation

KinetixUI is cross-platform design system infrastructure. Choose your platform first:

- **React** — use the registry or npm instructions below in an existing React app.
- **[Angular (Preview)](/docs/angular)** — Angular 21, standalone components, and plain CSS; the React CLI does not install Angular components.
- **[SwiftUI](/docs/swiftui)** — a local SwiftPM package from a repository checkout; iOS 16 / macOS 13 or newer.
- **[Jetpack Compose](/docs/compose)** — the Android library module from a repository checkout; no Maven Central install yet.
- **[Flutter](/docs/flutter)** — a local path dependency from a repository checkout; no pub.dev install yet.

The rest of this page covers **React with Tailwind CSS 3**. Tailwind 4 setup is not verified here.
Start with an app that already renders React and loads a global stylesheet. The CLI adds component source
and tokens; it does not create an app, configure Tailwind, or configure your import aliases.

React ships two ways. Both use the same tokens.

| What you install | Registry (own the code) | npm (versioned dependency) |
| --- | --- | --- |
| Components | `npx @kinetixui/cli add <name>` | `npm i @kinetixui/ui` |
| Tokens | `npx @kinetixui/cli init` | `npm i @kinetixui/tokens` |

The registry drops source into your repo (you edit it freely) via the
[kinetixui CLI](/docs/cli). The npm packages update with `npm update`.
Tokens are a good npm dependency; components are often nicer copied.

## Tokens

**Registry** — writes `:root` (light) + `.dark` + the shadow / type composites
into your global stylesheet:

```bash
npx @kinetixui/cli init
```

**npm** — import the generated CSS, or the typed object:

```css
@import "@kinetixui/tokens/css";
@import "@kinetixui/tokens/css/dark";
@import "@kinetixui/tokens/css/extras"; /* --shadow-* + --text-* */
```

```ts
import tokens from "@kinetixui/tokens";
tokens.color.blue[500]; // "#1b3c53"
```

Native text styles ship too: `KinetixType.swift`, `KinetixType.kt`,
`app_text.dart` under the package's `dist/{ios,android,flutter}`.

## A component

**Registry:**

```bash
npx @kinetixui/cli add button
```

The CLI resolves `tokens` first (a registry dependency), installs every npm
package the delivered files import — for `button` that is
`@radix-ui/react-slot`, `class-variance-authority`, `clsx` and `tailwind-merge`
— then drops `button.tsx` into your configured components directory.

`clsx` and `tailwind-merge` are there because `button.tsx` imports `cn()`, so
the item also delivers `lib/utils.ts`, which imports both. You do not install
them yourself: each item's dependencies are derived from every file it ships, and
`pnpm check:registry-deps` fails the build if one is ever missing.

Name several at once (`add button card dialog`), run `npx @kinetixui/cli
list` to see everything available, or pull the whole library in one go
with `npx @kinetixui/cli add --all`. See the [CLI reference](/docs/cli)
for every flag.

**npm** — every component ships in the one package, so there's no
per-component step:

```bash
npm i @kinetixui/ui @kinetixui/tokens
```

```tsx
import { Button, Field, FieldLabel } from "@kinetixui/ui";
```

## Tailwind

Install the preset's package for either React route, and install Tailwind's build tools if your app does
not already have them:

```bash
npm i @kinetixui/ui
npm i -D tailwindcss@3 postcss autoprefixer
```

Map the utilities onto the contract — KinetixUI ships a preset:

```ts
// tailwind.config.ts
import preset from "@kinetixui/ui/tailwind.config";

export default {
  presets: [preset],
  darkMode: ["class"],
  content: [
    "./src/**/*.{ts,tsx}",
    "./app/**/*.{ts,tsx}",
    "./components/**/*.{ts,tsx}",
    // npm components live outside src; scan their shipped source for utilities.
    "./node_modules/@kinetixui/ui/src/**/*.{ts,tsx}",
  ],
};
```

<Callout>
  The preset wires `colors`, `borderRadius`, `spacing`, `fontFamily` and the motion
  durations and easings to CSS variables. It also adds the `tailwindcss-animate`
  plugin, the accordion, collapsible, marquee, typing and caret keyframes, and a
  base rule that shortens every animation and transition to `0.01ms` under
  `prefers-reduced-motion: reduce`. It adds no reset.

  The registry (`npx @kinetixui/cli add`) delivers component source and the token
  stylesheet, **not** the preset. Without it, utilities such as `animate-in`,
  `duration-fast` and `ease-standard` do not exist, so those animations simply do
  not run, and there is no global reduced-motion rule. What a registry component
  does promise on its own is that every loop it ships stops under reduced motion.
  See [Foundations](/docs/foundations#motion).
</Callout>

## First working React component

For the **npm route**, load the token CSS and Tailwind layers in the global stylesheet that your app imports:

```css
@import "@kinetixui/tokens/css";
@import "@kinetixui/tokens/css/dark";
@import "@kinetixui/tokens/css/extras";

@tailwind base;
@tailwind components;
@tailwind utilities;
```

Use your existing PostCSS configuration, or create `postcss.config.cjs`:

```js
module.exports = {
  plugins: { tailwindcss: {}, autoprefixer: {} },
};
```

Replace your app's component with this example, then run its usual development command:

```tsx
"use client";

import { useState } from "react";
import { Button } from "@kinetixui/ui";

export default function App() {
  const [saved, setSaved] = useState(false);
  return (
    <Button variant="Primary" onClick={() => setSaved(true)}>
      {saved ? "Saved" : "Save"}
    </Button>
  );
}
```

You should see a styled **Save** button; clicking it changes the label to **Saved**.
An unstyled button usually means Tailwind is not running, the package source is absent from `content`,
or the global token stylesheet is not loaded.

For the **registry route**, run `npx @kinetixui/cli init` before `add button`, choose your real global
stylesheet, and configure `@/*` to resolve to the directory containing `components` and `lib` in both
TypeScript and your bundler. Import the copied Button from `@/components/ui/button` instead of
`@kinetixui/ui` (adjust to your configured components directory). Keep the CLI's token stylesheet and add
the Tailwind layers there; you do not need to import a second copy of the token CSS.

[Explore components](/components) once your first button works.
