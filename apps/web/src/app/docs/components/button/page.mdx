## React installation

Install the package the usage below imports from:

```bash
npm i @kinetixui/ui @kinetixui/tokens
```

The project also needs Tailwind CSS 3 and the KinetixUI preset; see [Installation](/docs/installation). To own
the source instead, copy it into your project with the CLI and import from the folder it writes to:

```bash
npx @kinetixui/cli add button
```

## React usage

```tsx
import { Button } from "@kinetixui/ui";

<Button variant="Primary" size="md">Save</Button>
<Button asChild variant="Link"><a href="/docs">Docs</a></Button>
```

## Pending

While the action a button started is in flight, pass `pending`. The button stays focusable and keeps its
name, a spinner appears in a slot that is reserved in both states so the label does not move, and
activation is suppressed for every input device — pointer, <kbd>Enter</kbd>, <kbd>Space</kbd>, touch and
implicit form submission.

```tsx
const [saving, setSaving] = React.useState(false);

<Button
  pending={saving}
  onClick={async () => {
    setSaving(true);
    try {
      await save();
    } finally {
      setSaving(false);   // both paths: pending is controlled, and nothing clears it for you
    }
  }}
>
  Save
</Button>
```

It is deliberately not `disabled`. `disabled` takes the control out of the interactive set, which moves
the focus the user just placed; `pending` sets `aria-disabled` and `aria-busy` instead, so the control
keeps its place and the status is announced politely from a live region outside the button — once per
transition, and separately from the button's name. Pass `pendingLabel` to localise that announcement; it
defaults to the English `"Working…"`.

Two rules worth knowing before you hit them. `disabled` wins over `pending`, because a control the author
has disabled is not doing anything. And `pending` cannot be combined with `asChild`: Radix's `Slot` takes
exactly one child, so the spinner has nowhere to go — that combination throws in development rather than
dropping `pending` silently.

`pending` is a state of the action, not a semantic variant, and it has a settled successor: move it back
to `false` on the confirmed path and the failed one alike, and show the outcome with
[`ResultState`](/docs/components/result-state).

`state="Pending"` is a different thing: the presentational `state` axis gains a `Pending` key so a docs
page, a playground or a visual snapshot can pin the appearance, exactly as `state="Disabled"` pins the
look of `disabled`. It draws the indicator and nothing else — no suppression, no `aria-busy`, no
announcement. The prop is the state; the axis is a picture of it.

## API

| Prop | Type | Default |
| --- | --- | --- |
| `variant` | `"Primary" \| "Secondary" \| "Outline" \| "Destructive" \| "Ghost" \| "Link"` | `"Primary"` |
| `size` | `"sm" \| "md" \| "lg" \| "icon"` | `"md"` |
| `state` | `"Default" \| "Hover" \| "Focus" \| "Active" \| "Disabled" \| "Pending"` | `"Default"` |
| | <small>presentational only — pins an appearance, changes no behavior</small> | |
| `pending` | `boolean` | — |
| `pendingLabel` | `string` | `"Working…"` |
| `asChild` | `boolean` | `false` |

Plus all native `<button>` attributes.
