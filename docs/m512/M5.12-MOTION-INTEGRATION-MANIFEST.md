## #636's native motion ledger failure: **missing platform registration**

Classified against the brief's own option list, by experiment, in this order:

1. On `main + #636` and on `main + #624 + #636` the gate says:
   `✗ SwiftUI/KinetixSelectionIndicator.swift: animates, but is in no motion family and is not listed
   in KNOWN_GAPS. Either wire it to the reader's setting, or record why it is still outstanding —
   silence is not a decision.` #636's diff touches **no contract file at all**.
2. Registering it fully on `main + #624 + #636` gives a different failure:
   `✗ native ledger: the selectionIndicator family has no direction vocabulary in DIRECTION_TERMS` —
   which is how **#636's dependency on #628/#630/#631 was found.** The brief's graph shows #636 as
   standalone; it is not.
3. Registering it fully on the four-platform candidate gives the decisive pair:

   ```
   ✗ SwiftUI: no test in packages/ui-swiftui/Tests/KinetixUITests/SelectionIndicatorTests.swift
     is NAMED for the forward direction.
       Found: "test Forward And Backward Travel Require Stable Geometry",
              "test Reduced Motion Removes Travel Even When Layout Is Stable"
   ✗ SwiftUI: … is NAMED for the reverse direction. [same list]
   ```

So it is a missing registration **whose correct fix exposes a second, deeper problem**. This is not a
naming oversight: `KinetixSelectionIndicator.animation(reduceMotion:stableGeometry:)` is a
**direction-agnostic** policy function, so no honest test name can carry "earlier → later" or "later →
earlier". #636's real forward/reverse evidence is a mounted simulator recording measured by
`packages/ui-swiftui/Acceptance/Selection/measure-selection.py` (ffmpeg raw-frame pixel sampling at
402×874 @ 60fps), run by hand per its README — which **no workflow reads** (see
`M5.12-FIVE-PLATFORM-CERTIFICATION-GAPS.md`).

### The remedy taken, and its measured cost

The gate offers its own remedy — "record why it is still outstanding" — so a `KNOWN_GAPS.SwiftUI` entry
was added naming the hand-run recording and the condition for removing it. Declared gaps rise 9 → 10.
**SwiftUI is deliberately NOT registered as a contract consumer, so no five-platform parity is
claimed.** The gate is not suppressed: it still refuses silence.

Both directions controlled:

| control | observed |
| --- | --- |
| remove the `KNOWN_GAPS` entry | `✗ … is in no motion family and is not listed in KNOWN_GAPS`, **exit 1** — the entry is load-bearing |
| with the gap declared, delete the reduced-motion wiring (`guard !reduceMotion && stableGeometry` → `guard stableGeometry`) | **exit 0, `check:native-motion ok`** — this gate no longer catches it |

That second result is the price of a declared gap and it is stated here rather than discovered later.
It is **partly** mitigated, from the same files: `SelectionIndicatorTests.swift` asserts
`animation(reduceMotion: true, stableGeometry: true)` is nil, so that mutation turns the SwiftUI suite
red — and `Native (SwiftUI)` is green on #636. The protection exists; it lives in the platform's own
suite rather than in the bookkeeping gate.
