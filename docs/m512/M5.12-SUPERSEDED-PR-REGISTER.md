## Superseded on `main` — verifiable today

### #608 — "Keep non-finite Progress bounds out of ARIA" → **CLOSE**

`main`'s `packages/ui/src/components/progress.tsx`, as merged by #626, carries a **strictly stronger**
guard than #608 proposes:

| | #608 | `main` |
| --- | --- | --- |
| guard | `const primitiveMax = max === Infinity ? undefined : max;` | `const primitiveMax = Number.isFinite(max) ? max : undefined;` |
| withholds `Infinity` | yes | yes |
| withholds `-Infinity` | **no** | yes |
| withholds `NaN` | **no** | yes |

`main` also guards the painted fraction (`value >= 0 && value <= limit && Number.isFinite(value)`),
which #608 does not. Confirmed behaviourally, not only by reading: `check:motion` on a built site
reports `non-finite Infinite maximum { max: '100', valuenow: '50', painted: 0.5 }`,
`non-finite Not-a-number maximum { max: '100', … }` and `non-finite Infinite measurement { max: '100',
valuenow: null, painted: 0 }`. So #608 would be a **regression** if merged now.

### #602 — "Align React Progress motion with its accessible value" → **CLOSE**

`mergeable_state: dirty`. The accessible-value half is on `main` via #626 (`value` and `max` now reach
the Radix Root), and the motion half is on `main` too — the indicator is `transition-transform
duration-base ease-standard motion-reduce:transition-none
data-[state=indeterminate]:transition-none`. `check:motion`'s 22 motion-required interactions include
the Progress cases and pass.
