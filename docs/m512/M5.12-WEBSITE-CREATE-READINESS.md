## 4. Finding: 9 of 12 site-header focus stops draw the browser's ring, not the house ring

**Measured tonight**, Chromium via Playwright against the running build, keyboard `Tab` sweep of the
header on `/`, in both colour schemes. Probe: `hdr-focus-probe2.mjs` (written to the repo root to
resolve `playwright`, **not committed**).

| header stop | light theme | dark theme |
|---|---|---|
| `KinetixUI` (logo link) | **UA auto 1px `rgb(16,16,16)`** | **UA auto 1px `rgb(238,238,238)`** |
| `Search… Ctrl K` (button) | house ring, `rgb(82,67,219)` 1px + 4px halo | house ring |
| `GitHub — 2 stars, 0 forks` | house ring, `rgb(82,67,219)` 2px | house ring, **`rgb(186,179,255)`** 2px |
| `Select theme` (button) | house ring, `rgb(82,67,219)` 1px + 4px halo | house ring |
| `01Docs` … `08IoT` (8 links) | **UA auto 1px `rgb(16,16,16)`** | **UA auto 1px `rgb(238,238,238)`** |

Page background: `rgb(255,255,255)` light, `rgb(11,17,40)` dark.

**The control is built into the measurement.** Three siblings in the same header — the search button,
the GitHub link and the theme button — draw the design system's ring: a transparent 2px outline plus a
`box-shadow`, and that shadow re-themes correctly from `rgb(82,67,219)` in light to `rgb(186,179,255)`
in dark, the same value `check:theme-isolation` asserts against `--ring`. The logo and the eight
numbered nav links set no ring of their own at all: `outline-style: auto`, `box-shadow: none`.

**Scoped honestly: this is not a WCAG failure.** The UA ring adapts to the colour scheme — dark on
white, light on the dark navy — so a visible, adequately-contrasting ring *is* drawn on all nine
stops, which is why `check:a11y-site` is silent across all 740 views and is right to be. The defect is
consistency and robustness:

1. The ring on those nine stops does **not** follow `--focus`/`--ring`. The green-ring theme that
   `check:theme-isolation` exercises at 5.59:1 re-themes the three siblings and leaves these nine
   un-themed.
2. It is 1px `auto` where the house ring is 2px plus a 4px halo — a thinner target on the primary
   navigation than on the icon buttons beside it.
3. **No gate covers it.** `check:theme-isolation`'s focus-ring assertions are for the *navigation
   menu* component, not for plain header anchors, so this can regress or spread silently.

Not repaired here: a header focus-ring change is a visual change to every page of the production site,
it is outside the twelve priority heads, and it overlaps the surface #557/#577 rewrite. Recorded for
the owner, with the fix shape obvious from the three siblings.
