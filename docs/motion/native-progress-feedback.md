# SwiftUI and Compose determinate progress feedback

The owner approved the progress-feedback scope proposed in #563. Progress and CircularProgress now share bounded fill interpolation on existing base (300ms) and linear tokens. Arbitrary numeric utility text and indeterminate loops remain separate. Initial values appear at their target; retargeting proceeds from the current fraction without a queued sequence. Negative values clamp to zero, values above 100 clamp to one, NaN resolves to zero and infinities resolve to the appropriate endpoint.

Both platforms read the real live system preference. Reduced motion settles the current target immediately. Compose rekeys only its fraction animation on preference changes, preserving the component; SwiftUI rekeys only the decorative fill/ring, leaving outer accessibility intact. Restoring normal motion does not replay old progress. Accessible progress exposes the exact target rather than intermediate frames. Compose ring center text uses the target and does not duplicate its semantics; SwiftUI publishes a target percentage and ignores the decorative children. No live-region announcement is introduced.

Evidence: full SwiftUI suite 95 passed, including four new resolver/compile cases. Full Compose build, lint and 128 tests passed, including five progress cases covering normal intermediate fractions in both directions, exact bar/ring target semantics, per-frame retargeting, clamping and live preference/restoration. The helper is observed inside a real Compose composition; these are headless tests, not rendered-device certification. Removing the live preference behavior fails the Compose regression; removing the SwiftUI preference guard fails its reduced resolver test. Both restored suites pass. The 49 guard tests and all five identity controls pass.
