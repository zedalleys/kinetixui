## The three findings that most change what happens next

**1. Five PRs would ship undocumented changes to published packages.** #640, #641, #642, #631 and #636
each change `packages/ui/**`, `packages/ui-angular/**` or `packages/ui-swiftui/**` and carry **no
changeset**. The release gates only ask whether a *pending changeset* is described in the curated note;
they never ask whether a source change has one. Any of them landing before 0.28.0 ships an accessibility
or motion behaviour change with no changelog line and no release-note sentence, with CI green.

**2. #637's acceptance suite is wired to nothing.** No workflow invokes `xcodebuild` or the `MotionHost`
scheme; `swift test` tests the package, not the Xcode project. `verification.json` records **nothing**
about the Sheet. So deleting `.accessibilityAddTraits(.isModal)` or the `onDisappear` guard would turn
no check red. The repair is sound; its regression protection does not exist.

**3. `motion.json` and `motion-consumers.json` are hand-authored.** No script writes them, so the
brief's "regenerate canonical files" instruction applies only to `verification.json` and
`platform-parity.json` — where regeneration produced **zero** changes, proving the candidates are
already fixed points. A four-way collision in the motion contract has to be resolved by hand, and a
naive union is unsafe: my first attempt imported a sentence that contradicted the promotion rule earlier
in the same note. It was caught, repaired, and the resolver patched so later merges cannot repeat it.
