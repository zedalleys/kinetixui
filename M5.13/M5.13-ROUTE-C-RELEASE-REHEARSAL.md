### Control 3 is a real, open hole
**Deleting the entire Progress compatibility paragraph — the thing #635 exists to add — passes every
release-note gate.** No check requires a note to describe a breaking DOM change; `-coverage` asserts
that each changeset *has an id listed*, not that the prose says anything. #638 cannot close it either:
it compares the note to the page, so it catches a note **altered after activation**, never an omission
that was never written.

I did **not** build a gate for this. A sound one has to decide what counts as a DOM-structure change in
a diff, and a weak version of it would fail open and read as covered — the brief asks this phase to
finish existing work, not to add a check it cannot make load-bearing tonight. It is recorded as a
candidate in the owner register: tie a `packages/ui` render-tree change to a required compatibility
paragraph, with a control that deletes the paragraph and must fail.
