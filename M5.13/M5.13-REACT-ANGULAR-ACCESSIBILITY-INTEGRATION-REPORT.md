## 2. What each PR actually changes

Measured from the diffs, not from the PR titles.

**#640 — the accessible value.** `packages/ui-angular/src/lib/primitives.ts`, 24 lines. It introduces
`limit()` (a non-positive or non-finite `max` falls back to 0–100) and `boundedValue()` (clamped, and
`null` for non-finite), then rebinds the host to `aria-valuenow="boundedValue()"` and
`aria-valuemax="limit()"`. Before this, the *painted* fraction was already clamped — the old `percent`
computed `Math.max(0, Math.min(100, …))` — but `aria-valuenow` was the **raw** input and `aria-valuemax`
the **raw** max. The defect was therefore only in what was announced, which is why the pre-existing test
"clamps a value outside the range instead of overflowing the track" could not see it. It still passes
with #640's binding removed (§4, control D2).

**#642 — the rendered cue.** 11 lines of component `styles` under `@media (forced-colors: active)`:
`:host` takes `background-color: Canvas` plus a `1px solid CanvasText` inset outline, and
`.kx-progress__bar` takes `background-color: CanvasText`. Plus the `progress` fixture and the gate
`scripts/angular-progress-forced-colors.mjs`.

**#641 — the interrupted reopen.** `packages/ui/src/components/popover.tsx` (and the mirrored registry
copy) replace `const Popover = PopoverPrimitive.Root` with a wrapper that carries a session id in
context, keys the portal by it, and preventDefaults a stale `onCloseAutoFocus` when the session id no
longer matches the committed one. Radix retains the old focus scope while the exit animation plays; a
logical reopen now starts a fresh scope so entry autofocus runs again, and the dying scope's focus
restoration is suppressed instead of yanking focus back to the trigger.

**6 of 8 fail.** The two that survive are the two that never exercise the reopen-focus path, which is
the right shape for a control: it discriminates, rather than reddening everything.

The failure text names the defect precisely. Five scenarios report `expected focus on
[role="dialog"][aria-label="Details"] input; actual: <button … aria-haspopup="dialog"
aria-expanded="true" data-state="open" …>` — the popover is open and focus is still sitting on the
trigger. The opt-out scenario fails differently and more usefully: its event receipt comes back
`['close', 'open']` where `['close', 'open', 'entry']` was expected, so no entry-autofocus event fired
on the reopen at all. That is the mechanism #641 describes, observed rather than quoted.

The fix was restored afterwards and the tree verified byte-identical to `4dec2ca7` (`git diff HEAD`
empty for that file, index reset).
