## 3. What the stack does, by source reading

**#633 — modal scope** (`Sources/KinetixUI/Sheet.swift`):
- scrim gets `.accessibilityHidden(true)`
- the content stack gets `.accessibilityElement(children: .contain)` and
  `.accessibilityAddTraits(.isModal)`
- the content stack gets `.accessibilityAction(.escape) { isPresented = false }`
- `.ignoresSafeArea(edges: .bottom)` becomes `.ignoresSafeArea(.container, edges: .bottom)`

**#637 — focus return**:
- a second `init(isPresented:onDismiss:content:)`, with the existing initializer delegating to it with
  `onDismiss: nil`, so the public API is additive
- `.onDisappear { guard !isPresented else { return }; onDismiss?() }` on the presentation — the guard is
  what makes a reopen-during-dismissal *not* fire a restore
- an Xcode acceptance host: `Acceptance/Sheet/MotionHost.swift` (127 lines), a `.xcodeproj`, a shared
  scheme, `MotionHostTests.swift` (108 lines) and a README

The host uses two separate `@AccessibilityFocusState(for: .voiceOver)` properties — one for the modal,
one for the background — and resolves the restore target as `openerMounted ? .opener : .fallback`,
which is the fallback path.

## 6. The acceptance suite is wired to nothing

This is the central finding of the phase, and it is measured, not inferred.

```
grep -rn "xcodebuild\|MotionHost\|xcscheme" .github/workflows/ scripts/ package.json
  → one hit, and it is scripts/gen-verification.mjs listing "xcodebuild" among allowed program names
grep -rn "Acceptance/Sheet" (all yml, mjs, json, md outside that directory)
  → no hits
```

So:
- **No workflow invokes `xcodebuild` or the `MotionHost` scheme.** `native-swiftui.yml` runs
  `swift build` and `swift test`, which compile and test the SwiftUI *package*; they do not open an
  Xcode project, do not boot a simulator and cannot drive `XCUIVoiceOverService`.
- The README states the intended procedure in words: "Run the MotionHost scheme's UI tests on a
  dedicated iOS 27 simulator with the installed Xcode toolchain." That is a hand-run instruction.
- **`verification.json` records nothing about the Sheet.** Searching the ledger for `Sheet`,
  `Sheet.swift` and case-insensitive `sheet` returns 0 evidence entries; the 12 lowercase `sheet`
  occurrences are all membership entries in component-name inventory lists. The repository's own
  verification ledger therefore does not know this acceptance evidence exists, and SwiftUI's tiers
  remain `build:22 headless:0 runtime:0`.

The consequence for the owner is concrete: if someone later deletes `.accessibilityAddTraits(.isModal)`
or the `onDisappear` guard, **nothing in CI goes red.** `swift build` still compiles, `swift test` still
passes, and the only thing that would have caught it is a suite nobody runs. The repair is sound; its
regression protection is not.

The README does carry its own negative control ("in a disposable copy change the
`testAudibleOpenerWithDismissalCallback` call to pass `suppressRestore: true`… the exact-target speech
assertion must fail"), which is the right design. It has the same problem: it is a hand-run control.

## 7. Findings

**E1 — Keyboard dismissal has code and no test.** #633 adds `.accessibilityAction(.escape)` and nothing
asserts it. Every acceptance test dismisses through the "Dismiss library sheet" button. §7 lists keyboard
dismissal as something to verify; it is currently verifiable only by reading the source.

**E2 — RTL is coupled to the reopen case.** `--rtl` is passed only when `reopen` is true, so the plain
opener-restore and fallback-restore paths are never exercised right-to-left. The README is honest about
this ("an RTL reopen 90 ms into dismissal") — it is a coverage limit, not a misstatement.

**E3 — No automated runner for the acceptance suite** (§6 above). This is the one I would put in front
of the owner, because the fix for it is a decision, not a diff: either a `macos-latest` job that runs
`xcodebuild test -scheme MotionHost -destination 'platform=iOS Simulator,…'` (VoiceOver automation on a
hosted runner is the open question), or an explicit, recorded acceptance that this suite is owner-run and
the repair is unguarded between runs.

**E4 — Three dead `vercel.json` entries on merge.** The stack adds `codex/m68-swiftui-sheet-modal` and
`codex/m682-sheet-focus` with `deploymentEnabled: false` to `vercel.json`, `apps/web/vercel.json` and
`apps/docs/vercel.json`. §5 says to exclude branch-only preview configuration, and that is what these
are. On merge both branch names cease to exist, so the entries become permanent dead weight in the
shared mutable registry — the same file that already carries five dead `codex/create-m1-*` entries and
that nine open PRs conflict on. Not a blocker; worth stripping during integration rather than carrying.
